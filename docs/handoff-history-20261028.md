### 모바일 그래픽 개선

- `App.tsx`의 설정을 네이티브 `details/summary`로 바꿨다. 850px 이하에서는 처음에 접혀 있고 데스크톱에서는 열려 있다. 모바일의 상단 설명과 요약을 줄이고 캔버스를 화면 너비까지 넓힌다. 세로 높이는 `clamp(390px, 100svh - 280px, 780px)`이다. 390×844 CSS 화면에서 의도한 3D 영역은 390×564이며, 실제 브라우저 레이아웃 측정은 완료하지 못했다. 재생·시점·슬라이더의 터치 영역도 넓혔다.
- 세로 `ball` 시점은 40도 화각과 공·홀·깃발의 투영 범위를 이용한다. 390×564 3D 렌더에서 기본 6m 시작 공의 지름은 약 13.1 CSS 픽셀이다. 결과 구도는 하단 카드가 홀을 가리지 않도록 여유를 둔다. 공의 물리 반경이나 공급된 좌표는 확대·변형하지 않는다.

- 잔디의 가까운 미세 결·노멀과 먼 표면의 부드러움을 구분한다. 잔디 끝은 카메라 앞에서 재사용하되 보이는 뿌리는 월드 좌표에 고정한다. 공 접지 그림자는 제공된 공 높이와 별개로 그린 면에 붙이고 높이에 따라 퍼짐·농도를 바꾼다. 홀 안쪽은 깊이 음영, 경사에 맞는 얇은 테두리와 접촉 음영을 사용한다. 태양 그림자는 그린 중심에 맞춘 2048 맵을 쓴다.

### 이전에 완료한 퍼팅 재생·코스 구현

- `PuttingScene.ts`에 `ready`·`rolling`·`result` 상태를 추가했다. 준비 중에는 선택한 경사 표시를 보여주고, 재생 중에는 격자·높낮이·방향 표시와 조준선을 줄이며, 결과에서는 종점 표시를 보여준다. 기본 격자는 켜져 있다.
- 자동 카메라는 입력 궤적의 현재 공 위치와 홀·깃대가 함께 들어오도록 화면 비율에 맞춰 구도를 계산한다. 카메라 버튼을 선택하거나 드래그·휠 등으로 직접 조절하면 수동 시점으로 바뀐다. 자동 버튼으로 다시 켤 수 있다. 동작 줄이기 설정에서는 재생 중 고정된 전체 구도를 사용한다.
- `App.tsx`에 진행 단계, 재생 중 남은 거리, 홀인/정지 결과 카드, 다시 보기·준비로 동작을 추가했다. `putting:complete` 메시지는 기존 `id`에 `outcome`, `remaining`, `duration`을 추가한다. 일시정지와 위치 탐색, 재생 속도를 유지하며 탐색 시에는 재생을 멈춘다. 결과에서 다시 재생하면 시작 공이 즉시 화면에 들어오게 한다.
- `src/core/playback.ts`는 진행 단계와 홀까지의 평면 거리를 계산한다. 결과는 공급된 `outcome`을 사용하며 홀과 가깝다는 이유로 홀인을 추정하지 않는다. 입력 좌표·시간·제공된 높이를 보존하고, 높이가 있는 궤적에는 임의의 홀인 낙하를 더하지 않는다. 느린 프레임에서도 궤적 시계는 실제 경과 시간을 따른다.
- 자연광과 그린 색을 조정하고 깎은 무늬의 대비를 줄였다. 그린 외곽과 프린지 폭을 불규칙하게 바꾸고, 경계 색을 보간한다. 퍼팅 면은 계속 입력 경사의 `heightAt` 평면과 일치한다. 기존 CC0 잔디 맵을 그대로 사용한다.
- `src/scene/CourseEnvironment.ts`를 추가했다. 완만한 외곽 지형, 여러 깊이의 나무 군락, 그라데이션 하늘과 구름을 생성한다. 나무는 줄기·가지·수관을 인스턴싱하며, 잎 텍스처는 코드로 생성한 원본이다. 추가 다운로드나 외부 이미지 생성 의존성은 없다.
- `src/scene/course.ts`에서 그린 외곽 모양과 주변 지형 높이를 공유한다. `PuttingScene.ts`의 퍼팅 면은 기존 `heightAt` 경사 평면을 유지하고, 프린지와 러프를 통해 주변 지형에 연결한다.
- `TurfMaterial.ts`는 기존 CC0 색·노멀·거칠기 맵을 유지하면서 그린·프린지·러프의 반복 크기와 색·노멀 강도를 구분한다. 미세한 그린 질감, 깎은 무늬와 넓은 명암 변화를 조정했다. 가까운 잔디 끝과 공의 접지 그림자도 조정했다.
- 공 뒤 기본 구도, 세로 화면 화각, 전체 보기와 탑뷰의 범위를 보정했다. 2m 퍼팅의 잔디 시점에서는 카메라가 뒤로 물러나 깃대가 잘리지 않게 했다. 카메라 전환 중 화각도 보간한다.

## 현재 프로젝트 구조

React, TypeScript, Three.js, Vite 기반의 `putting-lab` 프로젝트다. 카메라 전환, 거리와 경사 설정, 격자와 경사 방향 및 높낮이 표시, 궤적 불러오기와 시간 기반 재생, React Native WebView 메시지 연결이 있다.

기본 그린은 거리 6m, 스팀프 10ft, 좌우 경사 1.5%, 앞뒤 경사 0.5%다. 카메라 종류는 `ball`, `perspective`, `top`, `surface`다.

현재 샘플 궤적은 화면 확인용으로 작성한 데이터이며 실제 퍼팅 물리 계산이 아니다. 샘플은 경사에 맞춰 모양을 늘리거나 뒤집지만 재생 시간은 5.15초이고 홀인 결과를 사용한다. 스팀프 설정만으로 실제 공의 속도가 계산된다고 설명하면 안 된다. 실제 계산 결과를 연결하는 외부 궤적 인터페이스가 이미 있다.

궤적의 좌표 단위는 미터, 시간은 초다. `x`, `z` 좌표에 선택적인 `y`와 `t`를 받는다. 공급된 좌표와 시간을 보존하며 재생해야 한다. 영상과 비슷하게 보이게 만들기 위해 실제 궤적의 경로나 속도를 임의로 바꾸지 않는다.

## 제안한 구현 순서

### 1 코스 배경과 기본 카메라

첫 결과물은 6m 퍼팅 장면 하나로 잡는다. 공, 홀, 깃대와 배경의 비율을 맞추고 나무, 하늘, 러프와 완만한 주변 지형을 배치한다. 퍼팅 면은 입력 경사와 일치시키고 외곽 지형에 구릉을 추가한다. 기준 시점의 이미지를 저장해 현재 렌더와 참고 장면을 비교한다.

주요 대상은 `PuttingScene.ts`의 환경과 그린 생성, 카메라 설정, 조명이다. 기존 Three.js 구조로 진행하는 방향을 제안했다.

### 2 잔디와 자연광

짧게 깎인 그린과 주변 러프를 구분한다. 가까운 곳에는 미세한 잔디 질감을, 먼 곳에는 부드러운 표면과 넓은 명암 변화를 사용한다. 깎은 무늬와 공의 접지 그림자를 조정한다. 기존 `src/assets/turf/`의 색, 노멀, 거칠기 맵을 확인하고 활용한다.

### 3 준비와 재생 및 결과 화면

준비 중에는 선택적으로 격자와 목표 표시를 보여준다. 공이 움직일 때는 표시 밀도를 줄이고, 홀 주변을 확인하기 쉬운 시점으로 전환한다. 공이 멈추면 남은 거리와 홀인 여부를 표시하고 반복 재생할 수 있게 한다. 구체적인 전환 시점과 표시는 구현 중 캡처로 검토한다.

### 4 궤적과 기기 검증

외부 궤적의 좌표와 시간에 맞춰 공이 움직이는지 확인한다. 홀인과 빗나가서 멈춘 경우를 모두 검증한다. 웹과 WebView의 화면 크기, 실제 기기 성능을 확인한다. 이번 분석에서 새 성능 측정 결과를 얻은 것은 아니다.

## 검증과 도구 상태

타입 검사·프로덕션 빌드, 궤적/결과/자동 품질 테스트 10개, 가로·세로·모바일 렌더 검증을 사용한다. 빌드에는 Three.js를 포함한 큰 번들에 대한 기존 크기 안내가 남아 있다. 실제 모바일 기기 FPS는 측정하지 않았다. 이번 Windows 화면 자동화는 기존 Putting Lab 창의 현재 브라우저 URL을 충분히 확인하지 못해 정책상 중단됐으며 재시도하지 않았다. 따라서 React UI의 실제 브라우저 육안·터치 확인은 완료하지 못했다. CPU 렌더로 이를 대체했다고 주장하지 않는다. `http://127.0.0.1:5173/`의 페이지 및 App/CSS 소스는 HTTP 200 응답을 다시 확인했다.

```text
npm run typecheck
npm test
npm run build
npm run verify:render
npm run verify:render -- --portrait
npm run verify:render -- --phone
```

`verify:render`는 실제 씬의 픽셀 검사와 이미지 출력을 사용한다. 960×600, 390×520 및 `--phone`의 390×564에서 2–12m·최대 ±5% 경사의 퍼팅 면 정합, 네 카메라의 공·홀·깃대 프레이밍, 전체/탑뷰의 그린 외곽 프레이밍을 검사한다. 자동 시점의 정지 구도와 실제 이동 중 구도, 결과 카드 아래 여백, 시작 공의 최소 화면 크기, 경사 표시의 페이드, 외부 시간·높이 보존, 홀인/짧음/지나침, 일시정지·탐색·재생·반복 재생, 수동 시점 우선, 동작 줄이기, 지연 프레임의 시간 정합도 검사한다. 해상도/먼 배경의 동시 조절, 가까운 나무 유지, 정지 선명도 복원과 수동 품질 선택도 실제 씬에서 검사한다. 격자·경사 방향·높낮이·성능 우선 모드와 각 단계를 이미지로 렌더한다. CPU 렌더 결과만으로 모바일 FPS를 주장하지 않는다.

브라우저 자동 제어는 현재 주소를 확실히 확인하지 못해 중단됐고, 이후에는 브라우저 입력을 사용하지 않았다. 공개 영상 정보와 미리보기 이미지를 네트워크로 확보한 다음 yt-dlp와 기존 imageio-ffmpeg로 주요 구간과 프레임을 추출했다. 필요한 자료가 이미 로컬에 있다.

다시 추출할 필요가 있을 때 참고할 보조 파일은 `.tmp/fetch-video-reference.py`, `.tmp/youtube-tool.py`, `.tmp/extract-trackman-frames.py`, `.tmp/make-reference-comparison.py`다. yt-dlp는 `.tmp/video-tools/`에 설치했다. 네트워크 호출은 기본 실행 환경에서 연결되지 않아 허용된 네트워크 접근 실행으로 처리했다. 음성 자막 요청은 빈 응답이어서 전사 자료는 없다.
